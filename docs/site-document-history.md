# 規約・ポリシーの選択公開

## 操作

運営の「設定」から利用規約またはプライバシーポリシーを開き、「履歴」で対象の版を選ぶ。本文を確認して「変更履歴に公開する」で公開し、「履歴の公開を取り消す」で非公開へ戻せる。新しく記録された版と既存の履歴はすべて初期状態で非公開。操作権限は文書の編集と同じで、保護された規約・ポリシーは代表・副代表・顧問・SEに限定する。ほかの運営は履歴の閲覧だけができる。

最新版の「保存する」と過去版の公開は別操作。最新版を保存すると従来どおり公開本文が更新され、変更前の版は非公開の履歴に残る。過去版の公開／取消では最新版を変更しない。取消後も運営の履歴・復元用本文は削除しない。

メンバーは最新版ページの末尾にある「変更履歴」から公開された版の一覧と本文を開ける。最新版と同じくログイン前でも閲覧可能であり、運営の公開操作時にもその旨を示す。過去版には版の日時（日本時間）と「過去の版」、最新版へのリンクを表示する。公開一覧は20件ずつ読み込み、非公開・公開取消済み・文書の異なる版のURLでは本文を表示しない。ネットワーク障害は履歴0件と区別して再読み込みを案内する。

## データと権限

- `site_document_revisions` は運営専用の監査用本文・保存日時・保存者を維持する。一般会員・匿名はアクセスできず、運営も直接改ざん・削除できない。
- `site_document_published_revisions` は運営が公開を選んだ版のスナップショット。本文・版の日時・初期版フラグ・公開日時だけを持ち、保存者IDなどの内部情報は含めない。匿名／認証済みにはSELECTだけを許可する。
- 認証済みの運営は `set_site_document_revision_published` RPCを使う。公開文書の種類、実際の認証ユーザー・運営権限・役職・退会状態をDBで検証し、保護文書には上位役職を要求する。公開本文は履歴からコピーするため、クライアントから任意の本文を注入できない。
- 権限が必要な処理は非公開スキーマの関数に置き、search_pathを固定、呼び出し権限を限定する。公開切替は対象の履歴行をロックして直列化し、同じ状態への再操作は冪等とする。
- 公開履歴はキャッシュせず取得する。公開を取り消した後の新しいリクエストでは、一覧にも個別本文にも出さない。Next.jsの既存loading境界によりNot Found画面がHTTP 200でストリーム配信される場合があるが、非公開本文は返さない。

## 初期版・記録日時

移行時にDB本文が空の規約・ポリシーだけ、現在のアプリの既定文面を一字も変えずDBへ保存する。既にDBに文面がある場合は上書きしない。初期版の公開開始日は不明なので `is_initial_version` を付け、架空の改定日を表示しない。初回の変更で初期版を履歴へ記録し、`saved_at` はNULL・画面上は「初期版」とする。公開するかどうかは、この版も運営が選ぶ。

変更された本文の保存日時と保存者はサーバー時刻・認証ユーザーから決定する。クライアントの日時・ユーザーIDは監査の正本にしない。同じ本文の再保存は履歴を増やさず、改定日時も変更しない。取得障害時に既定文面を編集フォームへ入れて既存本文を上書きしないよう、運営側はエラーと再試行を表示する。
