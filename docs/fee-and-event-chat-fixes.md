# 会費表示とイベントのグループチャット

2026年11月18日。対象はPWAと共通のデータモデル。学生確認・承認条件は変更しない。

## 会費

`fee_settings.annual_fee`は今回徴収する会費、`admission_fee`は入会金単体。新規会員の合計は両者の和、継続会員は会費のみ。管理画面の設定を入会手続きと運営の支払い確認へ反映する。確認時・画面復帰時には再取得し、取得失敗時に固定金額へ戻さず再試行を表示する。

本番設定の読み取りでは会費1,000円・入会金500円だった。既存の保存値は変更せず、新規会員には合計1,500円を表示する。設定保存は整数・非負・DBの整数範囲を検証し、保存結果の行を取得して確認する。支払い確認も保存完了を待ち、失敗時に成功表示しない。

## イベントのチャット

- 運営のイベント作成・編集にLINEとInstagramの招待リンクを独立して保存する。InstagramのDB列は `events.instagram_group_link`。空欄で更新したリンクは削除する。複製時には両方のリンクを引き継がない。
- 参加登録完了画面と参加済みイベントの参加チケットに、設定されたサービスの参加ボタンとコピー操作を表示する。リンクを開いても案内を閉じず、後から詳細を開き直してアクセスできる。
- 通常のHTTPSリンクとして開き、コピーが拒否された場合は選択・コピー用のURL欄を表示する。リンク未設定時は運営への問い合わせを案内する。
- 旧LINE欄のInstagram招待リンクは自動で判別して表示し、編集時にはInstagram欄へ移す。専用欄の設定を優先する。招待コード・クエリは保持し、前後の空白と省略されたHTTPSは補正する。
- 対応ホストはLINEの `line.me`・`lin.ee`・`line.naver.jp` とInstagramの `instagram.com`・`ig.me`。HTTP、偽ドメイン、認証情報付きURLなどは招待リンクとして使用しない。

## 公開手順

1. `supabase/migrations/20261118080630_event_chats_and_fee_defaults.sql` と `20261118082639_fee_settings_history.sql` を順に本番へ適用する。既存の会費設定値は更新しない。Instagram列の追加、入会金の列デフォルト、会費設定の変更履歴を追加する。既存のRLSを維持する。
2. PWAのブランチを本番へ公開する。旧PWAは追加列を無視するためDBを先に更新できる。
3. 運営画面で各イベントの有効なInstagram招待リンクを設定する。実際のリンクは運営が用意する。

本番反映には別途ユーザーの公開指示を受ける。今回は本番DBへの書き込み・公開は行っていない。ネイティブアプリの画面への展開は今回の対象外。

- 共通ロジックの7テストを実行。新規／継続、0円、不正な金額、LINE・Instagram・旧欄・重複、URL補正、不正URLを確認。
- Chromeの320・390・1280px、日英で設定保存と会員側への反映、取得失敗と再試行、参加登録完了・参加チケットからの再アクセス、リンクを開いた後も案内を保持すること、コピー成功と拒否時の代替表示、編集・削除の保存内容を確認。実際のコンポーネントとHTTPのテスト応答を使用し、本番データには書き込んでいない。
- 運営の新規・継続の金額、支払い確認失敗時の成功抑制、会費取得失敗時の確定ボタン無効化、個別サービス、狭い画面のモーダルを追加確認。

## 短い語尾だけの改行

参加完了画面は見出しで状態が伝わるため、重複する説明を削除。通常・確認ダイアログの見出しと説明を `text-wrap: balance` で折り返し、長いURLなどには `overflow-wrap: anywhere` を適用する。チャットの復帰案内も行幅を均す。固定改行・一律の改行禁止・文字サイズ縮小は使わない。

Chromeの280〜1280pxの13幅・日英、200%文字サイズ、長いURLで表示を確認。元の日本語説明文を使った共通Dialog／AlertDialogの確認では、複数行時に語尾だけが残らないことを確認した。

## 会費設定の変更履歴

1,500円は現在の設定値の合計であり、将来も固定する額ではない。会費設定を変更すると会員向け表示と運営の確認金額が追従する。

変更日時・変更者・変更前後の会費／入会金／通貨を `fee_settings_history` に自動記録する。履歴は設定の保存・削除と同じトランザクションで確定し、同じ値の保存では増えない。履歴を記録できない場合は設定の変更も取り消される。トリガー関数は非公開スキーマに置き、認証された変更者をサーバー側で取得する。通常のクライアントには履歴の直接挿入・変更・削除・採番を許可しない。

履歴の閲覧は運営だけに許可。会費設定画面に変更者・日時と変更前後の新規合計を表示し、IDをカーソルとして20件ずつ追加取得する。変更者は会員情報との参照で表示し、氏名を履歴へ複製しない。アカウント削除後も認証IDと金額の記録は保持する。

移行時点の設定を初期記録として残す。導入前の変更日時や変更者は復元・推測しない。会員個別の入金履歴とは別の、金額設定の変更履歴である。

SQL回帰テストは `supabase/tests/fee-settings-history.sql`。開発用DBのトランザクション内で履歴用の移行と合わせて実行し、必ずロールバックする。実在会員の属性や認証アカウントは変更しない。設定のテスト変更・削除・復元と履歴をロールバックし、権限や記録の整合性を確認する。
