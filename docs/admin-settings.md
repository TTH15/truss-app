# 運営設定の一覧と編集

設定画面は「自分の設定」「メンバー向けの設定」の2グループとし、プッシュ通知・ガイドツアーの案内・利用規約・プライバシーポリシーを独立した行で表示する。クリックした項目だけをモーダルに読み込む。長いフォームはモーダル内でスクロールし、閉じると元の項目へフォーカスを戻す。

利用規約とプライバシーポリシーの編集は対象文書を固定する。既存のプレビュー・運営向け履歴・復元・保護文書の編集権限・任意の変更告知は維持する。規約本文や公開権限は今回変更しない。

通知モーダルは、ブラウザの許可・端末の購読・ログイン本人のDB登録を確認してON/OFFを表示する。確認できない場合は再試行を表示する。別の担当者の購読を本人の登録済み状態として表示しない。非対応端末ではモーダル内に非対応の状態を表示する。

## 規約・ポリシーの履歴の現状（2026年11月18日確認）

- 本番DBには `site_documents_archive_revision` トリガーと `site_document_revisions` が存在する。DB本文を更新したとき、空ではない旧本文・旧版の保存日時・保存者を履歴へ退避する。同じ本文の保存では増えない。
- 履歴のSELECTポリシーは `is_admin_safe()`。運営の管理画面では履歴を閲覧・ドラフトへ復元できるが、メンバー用の公開ページには履歴のUIがなく、過去版の読み取り権限もない。
- メンバーは最新版の本文と、DBで更新された版の最終改定日を公開ページで確認できる。
- 確認時点の本番DB本文は両文書とも空で、改定履歴は0件。公開ページはアプリ内の既定文面を表示している。
- 既定文面はDBの旧本文ではないため、そのまま初回保存すると現在表示中の既定文面は履歴に残らない。メンバーへの履歴公開を追加する場合は、初期版も記録する処理と、保存者情報を公開しない読み取り経路を合わせて設計する。今回、履歴の公開範囲は変更していない。

## 検証

Chromeの320・390・1440px・日英で、一覧にフォームが出ないこと、項目ごとのモーダル、画面内への収まり・スクロール、閉じた後のフォーカス、ガイドの保存失敗時の入力保持と再試行・再表示、文書ごとの編集と既存履歴、保護文書の編集制限を確認。通知の既存登録・OFF/ON・再表示・取得失敗と再試行・非対応表示はモックで確認し、実通知を送っていない。本番DBは構造・公開権限・件数の読み取りのみで、書き込みなし。
