# 登録承認・会費確認と運営チャットの未返信

## 状態の区別

- 登録承認は `users.approved` による所属・登録の確認。国内学生では承認だけで会費の支払い確認は完了しない。
- 個人の会費支払いは `users.fee_paid`。振込完了のチャットは自己申告であり、運営が入金を確認して会員詳細の「支払い確認」を行う。国内学生の承認済み・未払いは「非会員」と未払いの財布アイコンで表示される。
- 留学生区分は、既存仕様で承認時に支払い済み扱いになる。実際の振込記録と同じ意味ではない。この区分の処理は今回変更していない。
- `fee_settings_history` は個人の入金履歴ではなく、会費の金額設定を変更した履歴。

## 名前と返信状況

相手の名前は一覧14px・会話上部17pxに変更。一覧のプレビュー12px・会話本文16pxより大きい関係を保つ。

未返信は、会員の最後の発言に対し、まだ運営が個別に返信していない状態。既読とは独立している。一覧と会話上部のFont Awesomeのビックリマーク、件数付きの絞り込みで示す。印へのホバー・フォーカスとタップで、会員の最後の発言からの未返信日数（24時間単位、1日未満はその旨）を表示する。未返信一覧のプレビューには最後の会員発言を出す。

承認通知、学生証の再提出依頼、個別一括送信は `messages.is_automated`、一斉送信は既存の `is_broadcast` により除外する。過去の承認・再提出通知は既存の定型文でも判別する。分類情報のない過去の任意文面の個別一括送信は、通常の返信と区別できない。

個別返信の送信成功後に判定を更新し、送信失敗・既読化だけでは未返信を解除しない。会員側の最後の発言が挨拶・お礼でも、運営の返信がなければ未返信として扱う。「自分の表示から消す」は担当者本人の印・未返信一覧・リマインド対象から外す。会話や既読・全体の未返信判定は変更しない。ほかの担当者には影響せず、会員の新しい発言で再び対象になる。取り消しと、設定からの一括復元に対応する。

## 担当者ごとの設定とプッシュ通知

一覧右上の設定で、印のON/OFF、印を出すまでの日数（0〜30日）、返信忘れのプッシュ通知のON/OFF、通知までの日数（1〜30日）を保存する。初期値は印ON・即時表示、プッシュOFF・1日。保存先は担当者本人のDB行で、複数端末で共有される。担当者の切り替え、取得・保存失敗時の再試行にも対応する。通知ONには端末の許可と購読保存が必要。iPhone／iPadはホーム画面に追加したPWAから設定する。

定期処理は日本時間の毎日10時台に、通知ONの現役運営担当者と登録された購読を確認する。指定日数を超えた未返信を担当者ごとにまとめ、「返信を忘れていませんか？」「N件のチャットが未返信です。」と通知する。会員の本文・氏名はプッシュに含めず、メッセージ行も作らない。タップすると運営のチャット画面を開く。受信時のプッシュとは別の設定で、印のON/OFF・表示日数とも独立する。

同じ担当者と会員の最新発言の組み合わせは、いずれかの登録端末に送信成功したら配信済みとする。ほかの端末だけが失敗した場合に、同じ担当者へ再通知し続けない。返信・自分の非表示・通知OFF・退会・運営権限の解除で送信対象から外す。送信失敗・端末未登録を配信済みにせず、期限切れの購読は削除する。送信予約は10分の期限つきで同時起動の重複を防ぎ、途中で停止しても後から再試行できる。送信直後かつ配信記録前の障害では再送の可能性があるため、同じブラウザ通知タグで置換する。判定と配送の間の返信・設定変更には短い競合時間があり、既に配信した通知の撤回は行わない。1回の処理は最大1000件（担当者と問い合わせの組み合わせ）で、残りは次回に処理する。

`admin_chat_attention_preferences` と `admin_chat_attention_dismissals` は認証済みの本人かつ運営だけが読み書きできるRLSとする。配送履歴・候補予約RPCはservice roleのみ。匿名・一般会員・ほかの担当者には設定・非表示を公開しない。プレビュー環境は定期処理の送信をスキップする。

## 全履歴からの判定

管理者のみ実行できる `admin_chat_reply_status()` を追加。既存のRLSを使うSECURITY INVOKER関数で、通知と取消済みメッセージを除いた最後の発言をスレッドごとに取得する。会員・未認証には運営の返信状況を公開しない。

初期表示の1000件に含まれない古い未返信でも判定できるよう、代表メッセージをスレッドへ補完する。API取得に失敗したときは警告と再試行を表示し、読み込めている会話からの判定を残す。メッセージ・既読の保存方法や承認・入金条件は変えない。

### リマインドの公開手順

1. PR #4の4件のDB移行を時刻順に適用する。既存の `034_truss_push_subscriptions.sql` と `036_truss_withdrawal.sql` の適用も前提。
2. VercelのProduction環境にランダムな `CRON_SECRET` を登録する。既存のSupabase service role・VAPID公開鍵／秘密鍵も必要。現在の本番には `CRON_SECRET` がないため、公開作業で設定する。値をリポジトリ・ログへ残さない。
3. PWAを公開する。プロジェクトのRoot Directoryは `apps/web` であり、その直下の `vercel.json` から `0 1 * * *`（UTC）の定期実行が登録される。VercelはProductionの公開後のみ実行する。
4. 担当者が自分の設定で通知を有効にする。テスト用担当者・問い合わせで配信とチャット画面への遷移を確認する。現在の検証では実通知を送っていない。
5. Cronログの200応答と配信件数を確認。401は認証設定、503は配信失敗／必要な設定を確認する。失敗した予約の再試行は10分経過後に行う。ロールバック時はCronを無効にしてから旧アプリへ戻す。テーブルは先に削除しない。
