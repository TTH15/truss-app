# 登録承認・会費確認と運営チャットの未返信

## 状態の区別

- 登録承認は `users.approved` による所属・登録の確認。国内学生では承認だけで会費の支払い確認は完了しない。
- 個人の会費支払いは `users.fee_paid`。振込完了のチャットは自己申告であり、運営が入金を確認して会員詳細の「支払い確認」を行う。国内学生の承認済み・未払いは「非会員」と未払いの財布アイコンで表示される。
- 留学生区分は、既存仕様で承認時に支払い済み扱いになる。実際の振込記録と同じ意味ではない。この区分の処理は今回変更していない。
- `fee_settings_history` は個人の入金履歴ではなく、会費の金額設定を変更した履歴。

## 名前と返信状況

相手の名前は一覧14px・会話上部17pxに変更。一覧のプレビュー12px・会話本文16pxより大きい関係を保つ。

未返信は、会員の最後の発言に対し、まだ運営が個別に返信していない状態。既読とは独立している。黄色の「未返信」、件数付きの絞り込み、会話上部の印で示す。未返信一覧のプレビューには最後の会員発言を出す。

承認通知、学生証の再提出依頼、個別一括送信は `messages.is_automated`、一斉送信は既存の `is_broadcast` により除外する。過去の承認・再提出通知は既存の定型文でも判別する。分類情報のない過去の任意文面の個別一括送信は、通常の返信と区別できない。

個別返信の送信成功後に判定を更新し、送信失敗・既読化だけでは未返信を解除しない。会員側の最後の発言が挨拶・お礼でも、運営の返信がなければ未返信として扱う。手動の対応済み・返信不要の状態は今回追加していない。

## 全履歴からの判定

管理者のみ実行できる `admin_chat_reply_status()` を追加。既存のRLSを使うSECURITY INVOKER関数で、通知と取消済みメッセージを除いた最後の発言をスレッドごとに取得する。会員・未認証には運営の返信状況を公開しない。

初期表示の1000件に含まれない古い未返信でも判定できるよう、代表メッセージをスレッドへ補完する。API取得に失敗したときは警告と再試行を表示し、読み込めている会話からの判定を残す。メッセージ・既読の保存方法や承認・入金条件は変えない。

## 公開・検証

`20261118083854_admin_chat_reply_status.sql` を先に適用してからPWAを公開する。先行するイベントチャット・会費履歴の2移行も必要。本番反映には別途公開指示を受ける。

- 共通ロジックは10テスト通過。未読／既読、返信成功後、会員の再発言、通知・一斉送信、順序違いを確認。
- 開発用DBで移行と `supabase/tests/admin-chat-reply-status.sql` をトランザクション内で実行。1100件の自動通知・一斉送信・旧承認通知を超えて古い問い合わせを検出し、返信・取消・権限を検証。ロールバック後に列と関数が残っていないことを確認。
- Chromeの320・390・1280px・日英で名前の大小関係、未返信の印と件数・絞り込み、既読後の保持、送信失敗と成功、取得失敗時の再試行を確認。取得処理による古い会話の補完、取得失敗の通知、会員側では運営APIを呼ばないことも検証。
- 本番ビルド・型チェック・差分チェック通過。Lintは変更前と同じ既存エラー（運営チャット1件、DataContext2件）。一時検証ページ・Context公開・比較用ファイルは削除済み。本番データへの書き込みなし。
